Fact stores · Conditional logic · Semantic drift

You kept all the facts.
Lost half the meaning.

Distilling a document into atomic facts preserves most of the words. It discards the structure that makes the words mean something — the conditional connections, the conjunctions, the ordering that tells you what has to be true before something else can be true.

That gap is semantic drift. It is wider than it looks, and atomic coverage alone will not show it to you.

33%conditional bridges kept
55%compositional probes passed
47%composite drift

Illustrative numbers from a Lambda logging example throughout this page. The library produces these for any source document.

01 · The passage

Three facts that only matter together.

A single paragraph of AWS documentation. An LLM extracts the facts. Another writes new documentation from those facts alone. Walk through what happens at each stage.

The source document. Conjunctive structure highlighted.

The CloudWatch log group is created automatically, but only when all three conditions hold: the Lambda execution role has logs:CreateLogGroup and logs:PutLogEvents permissions, and the function completes at least one successful invocation.

Without all three, the function appears to run successfully — but no logs are written and no error is surfaced.

The phrase "only when all three conditions hold" explicitly encodes a conjunction. That conjunction lives in the relationship between facts, not in any single fact. When you atomize the document, you need to store the relationship separately — or it disappears.

Five atoms stored in the fact store.

f01The Lambda execution role needs logs:CreateLogGroup permission to create the log group.
f02The Lambda execution role needs logs:PutLogEvents permission to create the log group.
f03At least one successful invocation is required to trigger log group creation.
f04The CloudWatch log group is created automatically.
f05Without all three conditions, the function appears to run but writes no logs and surfaces no error.
Conditional edges — extracted, not stored
requiresf01 + f02 + f03 → f04  ·  all three must hold simultaneously for automatic creation
implies¬(f01 ∧ f02 ∧ f03) → f05  ·  silent failure when any condition is missing

Every atom is accurate. The store holds them all. The REQUIRES edge — that f01, f02, and f03 must hold at the same time — has no field in a flat atom store. It is extracted and then discarded.

Regenerated from the atom list only. Structural changes highlighted.

The CloudWatch log group is created automatically. The Lambda execution role needs logs:CreateLogGroup permission. The role also needs logs:PutLogEvents permission. At least one successful invocation is needed.

If any condition is unmet, the function appears to run but writes no logs and surfaces no error.

Every fact survived. The conjunction "only when all three hold" did not. A developer reading this might add logs:CreateLogGroup alone and expect logs to appear. The original made clear that all three are required simultaneously — and the regen does not.

02 · The conditional graph

Edges carry the logic atoms can't.

The library extracts five types of relationship between facts. Each type captures a failure mode that flattening erases.

Requires

The consequent is true only when all listed antecedents hold simultaneously. Lost most often: a conjunction becomes three independent conditions. The developer satisfies one and considers themselves done.

Implies

One fact alone is sufficient for another. Lost most often in causal chains: "A causes B causes C" becomes three unconnected claims. No one knows B is the cause.

Contradicts

Two facts cannot both hold. Regenerations frequently state both as conditions without noting they are mutually exclusive — producing an impossible setup.

Sequence

B presupposes A — order matters. Regenerated documents reorder steps because atoms carry no position. The reader tries step 3 before step 1 is done.

Left: the conditional graph the LLM extracts. Right: what the atom store holds. Ghost lines show where the REQUIRES junction was. Without it, f01, f02, and f03 look like independent options rather than simultaneous requirements.

03 · The measurement gap

The number that looks fine isn't the story.

The obvious metric for a fact store round-trip is atom coverage: what fraction of the original facts survived in the regeneration? For this example the answer is 94% — four of five atoms are present, correctly expressed. That score is not wrong. It just only measures nodes.

Same example, three metrics

Atomic F1
94%
Conditional bridge recall
33%
Entailment probes
55%

Atomic F1 alone would read this as a 94% success. CBR reveals two of three conditional edges were lost. The entailment probes confirm the damage: more than half of questions requiring multiple facts to answer came back wrong from the regenerated document.

The gap between atomic F1 and CBR is what the library was built to surface. A distillation that scores 94% on atom coverage and 33% on conditional bridge recall did not preserve 94% of the document's meaning. It preserved the vocabulary and lost the logic.

04 · What the library measures

Three layers, one composite.

Each metric catches a different failure mode. All three are needed because a document can pass one test and fail another.

1

Atomic F1 — did the content survive?

The library embeds every fact from the original and the regenerated document. A regen fact "matches" an original when cosine similarity clears the threshold. Precision measures hallucination rate; recall measures coverage. F1 is the harmonic mean. Weight in composite: 25%. This is a floor check, not a ceiling — high F1 is necessary but tells you nothing about structure.

2

Conditional bridge recall — did the structure survive?

Facts in both graphs are matched by embedding similarity. For each original conditional edge, the library checks whether the mapped edge of the same type exists in the regen graph. Edges are weighted by their extraction confidence. CBR broken out by edge type shows which kind of relationship the regeneration most reliably drops. Weight in composite: 50% — double, because atomic F1 cannot see this failure at all.

3

Entailment probes — does the regeneration behave correctly?

The library generates yes/no questions that require multiple facts to answer — specifically targeting REQUIRES edges with two or more antecedents. It then queries the regenerated document with each question. The pass rate is a behavioral measure of whether the conjunctive structure actually disappeared from the reader's experience, even if CBR missed it. Weight in composite: 25%.

4

Structural drift — did the prerequisite ordering survive?

For procedure pages, the library runs the prerequisite extractor on both documents and compares: how many prerequisites survived, how much more detour-prone the regeneration became, how far introduction positions shifted. See §05 for the connection to the detour assessment. Added when applicable; renormalizes other weights.

The composite drift score is the weighted average of the loss terms (1 − score) for applicable layers. Zero means perfect preservation. One means complete loss. For this example:

6%atomic loss
67%CBR loss
45%entailment loss
47%composite drift

05 · The structural layer

Prerequisite ordering is also drift.

The metrics above work at the paragraph and sentence level: did individual facts survive, did the conditional logic between adjacent claims survive? A document also carries structure at a higher level.

A how-to page has a job. It tells the reader what to have ready before they start. It surfaces those prerequisites early, with enough context to satisfy them. That ordering is a form of meaning — and it can be lost in a fact store round-trip even when every individual fact is correctly preserved.

The original document introduced all prerequisites in a checklist at the top. The regenerated document embedded them in the steps where they were needed — the classic detour pattern. The atoms were intact. The structure was not.

The detour assessment measures this in original documents: what fraction of prerequisites are detours, how often links deliver what they promise. The drift pipeline extends that measurement to the round-trip: compare the prerequisite tree the original had to the tree the regeneration produced.

What structural drift measures

Prerequisite recall — what fraction of original prerequisites are present in the regeneration, matched by word overlap.

Detour rate delta — how much more detour-prone the regenerated document became. A positive delta means the regeneration springs prerequisites on the reader at point-of-need rather than up front.

Introduction position MAE — how far matched prerequisites moved within the document, normalized by page length.

For this example

Prereq recall
60%
Orig detour rate
20%
Regen detour rate
42%

The regeneration introduced 22 percentage points more detours. Two of five prerequisites were dropped entirely. The document that looked fine on atomic coverage sends the reader on more unplanned side trips than the original.

06 · Running it

One script. One report.

The pipeline is a single script in experiments/doc_drift/. Pass a URL or a local file. It fetches, extracts, regenerates, re-extracts, and scores.

python -I experiments/doc_drift/run.py <url-or-file>
python -I experiments/doc_drift/run.py <url> --no-structural   # skip ordering layer
python -I experiments/doc_drift/run.py <url> --json            # machine-readable

Reading the report

Atomic loss below 10% with CBR loss above 50% is the typical pattern for a well-formed but structurally hollow regeneration. Entailment loss above 40% confirms readers will encounter wrong answers. A composite above 40% warrants investigation regardless of atomic coverage.

Using the Python API

The metrics are importable from semantic_ruler.drift as pure functions: atomic_f1, cond_bridge_recall, entailment_rate, structural_drift, drift_score. The shared shard store caches extracted graphs, so the LLM extraction cost is paid once per document.
