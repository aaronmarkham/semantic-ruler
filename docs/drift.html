Drift in the Fact Store

Fact stores · Conditional logic · Semantic drift

You kept all the facts.
Lost half the meaning.

Distilling a document into atomic facts preserves most of the words. It discards the structure that makes the words mean something: the conditional connections, the conjunctions, the ordering that tells you what has to be true before something else can be.

That gap is semantic drift. It is wider than it looks, and atomic coverage alone will not show it to you.

94%atomic facts preserved
33%conditional bridges kept
55%compositional probes passed
47%composite drift

Illustrative numbers from a Lambda logging example throughout this page. The library produces these for any source document.

01 · The passage

Three facts that only matter together.

A single paragraph of AWS documentation. An LLM extracts the facts. Another writes new documentation from those facts alone. Walk through what happens at each stage.

The source document. Conjunctive structure highlighted.

The CloudWatch log group is created automatically, but only when all three conditions hold: the Lambda execution role has logs:CreateLogGroup and logs:PutLogEvents permissions, and the function completes at least one successful invocation.

Without all three, the function appears to run successfully — but no logs are written and no error is surfaced.

The phrase "only when all three conditions hold" encodes a conjunction. The conjunction lives in the relationship between the facts, and no single fact carries it. Atomize the document and you have to store that relationship separately, or it disappears.

Five atoms stored in the fact store.

f01The Lambda execution role needs logs:CreateLogGroup permission to create the log group.
f02The Lambda execution role needs logs:PutLogEvents permission to create the log group.
f03At least one successful invocation is required to trigger log group creation.
f04The CloudWatch log group is created automatically.
f05Without all three conditions, the function appears to run but writes no logs and surfaces no error.
Conditional edges: extracted, then dropped
requiresf01 + f02 + f03 → f04  ·  all three must hold simultaneously for automatic creation
implies¬(f01 ∧ f02 ∧ f03) → f05  ·  silent failure when any condition is missing

Every atom is accurate. The store holds them all. The REQUIRES edge, that f01, f02, and f03 must hold at the same time, has no field in a flat atom store. The extractor finds it and the store drops it.

Regenerated from the atom list only. Structural changes highlighted.

The CloudWatch log group is created automatically. The Lambda execution role needs logs:CreateLogGroup permission. The role also needs logs:PutLogEvents permission. At least one successful invocation is needed.

If any condition is unmet, the function appears to run but writes no logs and surfaces no error.

Every fact survived. The conjunction "only when all three hold" did not. A developer reading this might add logs:CreateLogGroup alone and expect logs to appear. The original said all three are required at once. The regeneration says nothing of the kind.

02 · The conditional graph

Edges carry the logic atoms can't.

The library extracts five types of relationship between facts. Each type captures a failure mode that flattening erases.

Requires

The consequent is true only when all listed antecedents hold simultaneously. Lost most often: a conjunction becomes three independent conditions. The developer satisfies one and considers themselves done.

Implies

One fact alone is sufficient for another. Lost most often in causal chains: "A causes B causes C" becomes three unconnected claims. No one knows B is the cause.

Contradicts

Two facts cannot both hold. Regenerations often state both as conditions without saying they exclude each other, and the result is a setup nobody can build.

Sequence

B presupposes A, so order matters. Regenerated documents reorder steps because atoms carry no position. The reader tries step 3 before step 1 is done.

Left: the conditional graph the LLM extracts. Right: what the atom store holds. Ghost lines show where the REQUIRES junction was. Without it, f01, f02, and f03 look like independent options. The original needs all three at once.

03 · The measurement gap

The number that looks fine counts only nodes.

The obvious metric for a fact store round-trip is atom coverage: what fraction of the original facts survived in the regeneration? For this example the answer is 94%: four of five atoms are present and correctly expressed. That score is accurate, and it measures nodes alone.

Same example, three metrics

Atomic F1
94%
Conditional bridge recall
33%
Entailment probes
55%

Atomic F1 alone reads this as a 94% success. CBR shows that two of three conditional edges are gone. The entailment probes confirm the damage: the regenerated document answered more than half of the multi-fact questions wrong.

The library exists to surface the gap between atomic F1 and CBR. A distillation that scores 94% on atom coverage and 33% on conditional bridge recall kept the vocabulary and lost the logic.

04 · What the library measures

Three layers, one composite.

Each metric catches a different failure mode. You need all three because a document can pass one test and fail another.

1

Atomic F1 — did the content survive?

The library embeds every fact from the original and the regenerated document. A regen fact "matches" an original when cosine similarity clears the threshold. Precision measures hallucination rate; recall measures coverage. F1 is the harmonic mean. Weight in composite: 25%. Treat it as a floor: a regeneration needs high F1, and high F1 says nothing about structure.

2

Conditional bridge recall — did the structure survive?

The library matches facts across the two graphs by embedding similarity, then checks, for each original conditional edge, whether the regen graph has the mapped edge of the same type. Each edge counts by its extraction confidence. CBR broken out by edge type shows which kind of relationship the regeneration drops most often. Weight in composite: 50%, double the others, because atomic F1 cannot see this failure at all.

3

Entailment probes — does the regeneration behave correctly?

The library writes yes/no questions that take several facts to answer, aimed at REQUIRES edges with two or more antecedents, and puts each one to the regenerated document. The pass rate measures behaviour: whether the conjunctive structure disappeared from the reader's experience, even where CBR missed it. Weight in composite: 25%.

4

Structural drift — did the prerequisite ordering survive?

For procedure pages, the library runs the prerequisite extractor on both documents and compares: how many prerequisites survived, how much more detour-prone the regeneration became, how far introduction positions shifted. See §05 for the connection to the detour assessment. Added when applicable; renormalizes other weights.

The composite drift score is the weighted average of the loss terms (1 − score) for applicable layers. Zero means perfect preservation. One means complete loss. For this example:

6%atomic loss
67%CBR loss
45%entailment loss
47%composite drift

05 · The structural layer

Prerequisite ordering is also drift.

The metrics above work at the paragraph and sentence level: did individual facts survive, did the conditional logic between adjacent claims survive? A document also carries structure at a higher level.

A how-to page has a job. It tells the reader what to have ready before they start. It surfaces those prerequisites early, with enough context to satisfy them. That ordering is meaning too, and a fact store round-trip can lose it while preserving every individual fact.

The original document introduced every prerequisite in a checklist at the top. The regenerated document buried each one in the step that needs it: the detour pattern from the map. Intact atoms, scrambled order.

The detour assessment measures this in original documents: what fraction of prerequisites are detours, how often links deliver what they promise. The drift pipeline extends that measurement to the round-trip: compare the prerequisite tree the original had to the tree the regeneration produced.

What structural drift measures

Prerequisite recall — what fraction of original prerequisites are present in the regeneration, matched by word overlap.

Detour rate delta — how much more detour-prone the regenerated document became. A positive delta means the regeneration springs prerequisites on the reader at the step that needs them instead of listing them up front.

Introduction position MAE — how far matched prerequisites moved within the document, normalized by page length.

For this example

Prereq recall
60%
Orig detour rate
20%
Regen detour rate
42%

The regeneration added 22 percentage points of detours and dropped two of five prerequisites outright. The document that looked fine on atomic coverage sends the reader on more side trips than the original.

06 · Running it

One script. One report.

The pipeline is a single script in experiments/doc_drift/. Pass a URL or a local file. It fetches, extracts, regenerates, re-extracts, and scores.

python -I experiments/doc_drift/run.py <url-or-file>
python -I experiments/doc_drift/run.py <url> --no-structural   # skip ordering layer
python -I experiments/doc_drift/run.py <url> --json            # machine-readable

Reading the report

Atomic loss below 10% with CBR loss above 50% is the typical pattern for a well-formed but structurally hollow regeneration. Entailment loss above 40% means readers will get wrong answers. A composite above 40% deserves a look whatever the atomic coverage says.

Using the Python API

Import the metrics from semantic_ruler.drift as pure functions: atomic_f1, cond_bridge_recall, entailment_rate, structural_drift, drift_score. The shared shard store caches extracted graphs, so you pay the LLM extraction cost once per document.
